\chapter*{Introduction}
\addcontentsline{toc}{chapter}{Introduction}

Public-key cryptography was introduced in the 1970s as a way to solve the
problem of secure communication without first sharing a secret key through a
secure channel. Its basic idea is to use mathematical operations that are easy
to perform in one direction, but difficult to reverse without secret
information. Because of this, the security of many public-key systems depends
on computational problems that are believed to be hard, such as integer
factorization or discrete logarithms.

The problem most relevant to this thesis is the subset-sum problem. Given a
sequence of positive integers and a target sum, the problem asks whether some
subset of the sequence has sum equal to the target. In knapsack cryptosystems,
public weights corresponding to message bits equal to $1$ are added during
encryption.

The first well-known cryptosystem based on this idea was proposed by Merkle and
Hellman~\cite{MerkleHellman1978}. Its construction uses a private
superincreasing sequence, for which the subset-sum problem can be solved
directly by a greedy algorithm. This private sequence is transformed by modular
multiplication, and optionally by a permutation, into a public key that is
intended to look like a general subset-sum instance. The legitimate receiver
can reverse the transformation and solve the easy private problem, while an
attacker sees only a public knapsack that appears to be a hard subset-sum
instance. However, the public knapsack is still generated from the private
superincreasing sequence. If the public key leaks useful information about the
private sequence, an attacker can try to recover an equivalent trapdoor or
solve ciphertexts directly.

This is what happened to the original Merkle--Hellman cryptosystem.
Shamir~\cite{Shamir1982} showed that an equivalent trapdoor can be recovered in
polynomial time. Later work also showed that several modified knapsack
constructions remained vulnerable. Brickell~\cite{Brickell1984} attacked
iterated variants through their structure, and Lagarias and
Odlyzko~\cite{LagariasOdlyzko1985} showed that some low-density subset-sum
instances can be solved directly with lattice reduction.

The aim of this thesis is to study this development through the classical
Merkle--Hellman cryptosystem and selected variants. The thesis focuses on how
the construction works, why the hidden superincreasing structure leads to
weaknesses, and how later variants tried to avoid these problems. It does not
propose a new secure knapsack cryptosystem, but treats the topic as a
historical and educational case study.

The practical part complements the theoretical discussion with an implementation
of the classical, permuted, and iterated variants in C. The experiments
compare the implemented variants, examine selected key-generation parameters,
and test simple subset-sum solvers on small instances.

This makes them useful mainly as an example of why an NP-complete problem does
not guarantee security when the cryptosystem generates structured public
instances.
